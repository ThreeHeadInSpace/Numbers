# Визуальная демоверсия на GitHub Pages

Адрес: https://threeheadinspace.github.io/Numbers/

Эта публикация предназначена для проверки существующего интерфейса. Она использует те же React-компоненты, стили, шрифты и адаптивную вёрстку. Это отдельная статическая сборка; Node/Hono, Better Auth, SQLite, OAuth, ЮKassa и DeepSeek на Pages не запускаются.

## Сборка и проверка локально

Требуется Node.js 24.15+ ветки 24; в Actions используется 24.18.0.

```text
npm ci
npm test
npm run build:demo
npm run check:demo
npm run preview:demo
```

Открыть http://127.0.0.1:4173/Numbers/ . Предварительный просмотр обслуживает только `dist/pages`; серверный API для него не нужен. Чтобы проверить дизайн на телефоне в своей локальной сети, можно явно запустить `npm run preview:demo -- --host 0.0.0.0` и открыть адрес компьютера с тем же путём `/Numbers/`.

`build:demo` использует Vite mode `pages-demo`, `base: /Numbers/` и отдельный каталог `dist/pages`. Файлы `.env*` при этой сборке не читаются, клиентские переменные окружения не экспортируются. Все шрифты и изображения загружаются с этого же сайта. `check:demo` проверяет пути HTML/CSS, наличие ресурсов и отсутствие серверных модулей, секретов и адресов API платёжной системы/модели в опубликованном артефакте.

Обычные команды `npm run dev`, `npm run build`, `npm start`, `npm run smoke` сохраняют прежний смысл: полноценное приложение для Node-хостинга, сборка в `dist/client` и `dist/server`, настоящие интеграции только через backend.

## Что работает в демонстрации

1. Расчёт числа жизненного пути и бесплатная интерпретация выполняются общим модулем `shared/numerology.ts` прямо в браузере. Мастер-числа 11/22/33 обрабатываются тем же алгоритмом.
2. «Войти» → «Попробовать демо-вход» открывает тестовый кабинет «Исследователь (демо)» с примером готового прогноза за предыдущую неделю.
3. После бесплатного расчёта можно пройти существующую покупку за 149 ₽: подтверждение → демооплата → готовый прогноз из локального шаблона. Денег и платёжных данных нет; цена — элемент визуального примера.
4. Сохранение даты, история, статусы заказа, повторное открытие текста, выход и сброс демоданных работают в текущей вкладке через `sessionStorage` с отдельным ключом `chisla.pages-demo.v1`.
5. Настоящие OAuth-кнопки отключены. Никакие ключи, API, база, серверная аналитика и внешние запросы для расчётов/входа/оплаты/прогнозов не используются. Неизвестный вызов демоадаптера возвращает локальную ошибку, а не пытается обратиться к серверу.

Данные сохраняются при обновлении вкладки и теряются при её закрытии/очистке хранилища. Не используйте публичную демоверсию для настоящих заказов. Если браузер запрещает хранилище, адаптер работает в памяти на время просмотра. Поля, документы и пояснения остаются частью проверяемого интерфейса, юридические страницы — шаблоны.

## Навигация

GitHub Pages не предоставляет server-side SPA rewrites, поэтому только демоверсия использует hash-маршруты:

- Главная: `/Numbers/`
- Кабинет: `/Numbers/#/account`
- Готовый пример: `/Numbers/#/forecast/demo-example-week`
- Документы: `/Numbers/#/legal/privacy`, `/Numbers/#/legal/agreement`, `/Numbers/#/legal/service`, `/Numbers/#/legal/contacts`
- Блоки главной: `/Numbers/#how`, `/Numbers/#weekly`, `/Numbers/#faq`

Ссылку на кабинет, документ или прогноз можно отправить и обновить в браузере без 404. В новой вкладке для личных примеров может потребоваться демо-вход. У обычного Node-приложения сохранены исходные адреса `/account`, `/forecast/:id` и `/legal/:id`.

## Автоматическая публикация

Workflow `.github/workflows/pages.yml` запускается при push в `main` и вручную через Actions → Deploy visual demo to GitHub Pages → Run workflow.

Он устанавливает зависимости по lockfile, запускает тесты, проверяет прежнюю production-сборку и smoke, отдельно собирает и проверяет demo, после чего публикует **только `dist/pages`** через официальные `upload-pages-artifact`/`deploy-pages`. Серверный build, исходники, `.env`, SQLite и backups в Pages artifact не включаются. Собственные repository secrets для этого workflow не нужны.

## Настройки GitHub

Для первоначального включения Pages у администратора репозитория:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. **Settings → Actions → General**: Actions включены; разрешены официальные `actions/*`, используемые workflow.
3. Если у environment `github-pages` вручную включены обязательное одобрение или ограничения веток, разрешить deployment из `main` либо одобрить запуск.
4. Убедиться, что HTTPS включён для стандартного `github.io`-адреса. Custom domain не требуется.

Если Pages уже включены через API в ходе публикации, первый пункт повторять не нужно. Настройка выполненного развёртывания и ссылка на успешный Actions run будут приведены в итоговом сообщении.
